# MyMechEngAgency

MyMechEngAgency is a prototype web front end for an AI-assisted mechanical-engineering analysis workflow.  Users submit a short PDF problem statement, optionally add hints/model overrides, and receive an HTML transcript generated by the MyAgency core.

This repository is intended as the initial clean release of the working Flask prototype.

## What is included

- Flask web interface
- MyAgency core code under `core/`
- queue/background worker
- MyAgency Handle + Access Code identity system; no email required
- job names and original PDF filename display
- optional `PROBhints.txt` upload
- optional `PROBgpt_models.yaml` upload
- continuation/follow-up questions appended to the same transcript
- 48-hour job cleanup policy
- local Miniforge installer
- GitHub-safe `.gitignore`

## What is not included in Git

The following are intentionally ignored:

- `miniforge3/`
- `jobs/`
- `results/`
- `uploads/`
- `logs/`
- `secrets/openai.env`
- zip files and OS/Python cache files

Do not commit real API keys, generated job results, logs, or the Miniforge installation.

## Local installation on Mac or Linux

From the top-level folder:

```bash
bash create_python_environment.sh
bash install_local.sh
```

A fresh install creates:

```text
./miniforge3
```

inside the project folder. Re-running the installer should reuse the existing Miniforge installation.

## OpenAI API key

For local/private testing, place the server-side key in:

```text
secrets/openai.env
```

with content like:

```bash
export OPENAI_API_KEY="sk-..."
```

If this file is blank or absent, the Submit page asks the user to provide an OpenAI API key for that job only.

## Running locally

Start the Flask app and worker:

```bash
bash start_server.sh
```

Then open:

```text
http://127.0.0.1:5000
```

Stop the worker/server with Ctrl-C, or use:

```bash
bash stop_worker.sh
```

if the worker was left running.

## User flow

1. New user creates a MyAgency ID.
2. The system generates:
   - MyAgency Handle
   - Access Code
3. User submits a PDF problem statement.
4. Optional uploads:
   - hints file, saved internally as `PROB/PROBhints.txt`
   - model override file, saved internally as `PROB/PROBgpt_models.yaml`
5. MyAgency creates the transcript in the job's `PROB` directory.
6. The web page links to the HTML result.
7. Completed jobs can be continued with follow-up questions; each follow-up reads the current augmented transcript and appends the new Q&A to the same transcript and HTML file.

## Limits and defaults

The web app has conservative demo defaults:

- PDF page limit: 5 pages
- upload size limit: 25 MB
- max active jobs: 10
- max analysis jobs per MyAgency ID per day: 3
- max analysis jobs per IP per day: 10
- job retention: 48 hours

These can be overridden with environment variables:

```bash
MYAGENCY_MAX_PDF_PAGES=5
MYAGENCY_MAX_UPLOAD_MB=25
MYAGENCY_MAX_ACTIVE_JOBS=10
MYAGENCY_MAX_JOBS_PER_USER_DAY=3
MYAGENCY_MAX_JOBS_PER_IP_DAY=10
MYAGENCY_JOB_RETENTION_HOURS=48
MYAGENCY_ADMIN_PASSWORD=...
MYAGENCY_FLASK_SECRET=...
```

## GitHub first push

Before pushing, confirm:

```bash
git status --ignored
```

The ignored list should include `miniforge3/`, logs, results, jobs, uploads, and `secrets/openai.env`.

Then from this top-level folder:

```bash
git init
git add .
git commit -m "Initial MyMechEngAgency release"
git branch -M main
git remote add origin https://github.com/apatera1958/MyMechEngAgency.git
git push -u origin main
```

If GitHub authentication is needed, use GitHub CLI:

```bash
gh auth login
```

Do not use your GitHub account password for Git pushes.

## Render direction

For Render deployment, this repository will likely be connected through GitHub. Render will use a web service for Flask and a worker process for the queue. The OpenAI key should be supplied through Render environment variables, not committed to the repository.

## AWS direction

For AWS EC2 deployment, copy or clone the repository on an Ubuntu VM, run the local installer, verify with the public IP, then later add Gunicorn/Nginx/HTTPS for robustness.
